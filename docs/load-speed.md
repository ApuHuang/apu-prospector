# 載圖速度量測（2026-10-27）

使用者回饋「載圖可以再快一點」。這份文件記錄量測方法、時間花在哪裡、改了什麼、改前改後的數字，
以及試過但沒有採用的做法。

**結論**：大部分時間花在我們控制不了的地方：從台灣到 CDS（法國）每個請求往返約 250 ms，每張切圖 0.6–1.5 秒；
每個 FITS 疊加圖層（Hα、塵埃）一開就要下載約 11 MB 的 Allsky.fits。這次確定有效的修正是：

- 「IFN / 塵埃」的 IRIS 圖層原本**完全載不出來**（40 秒以上），現在約 5 秒；
- 手機上「框中心」的 Hα／塵埃數值原本**永遠是「…」**，現在切圖一到就顯示；
- 線上版的天圖程式和目錄提早開始下載，「載入天圖中…」早約 0.25 秒消失；啟動時少一個被中斷重送的 hips2fits 請求。

一般開啟和拖曳的速度沒有變；能讓再次開啟快 0.6 秒的做法（固定鏡像網址）會讓剛開啟時的拖曳變慢，所以沒有採用。

## 量測方法

- 地點：台灣，家用網路。到 CDS 斯特拉斯堡的 TCP 往返約 230–260 ms，新連線（TCP＋TLS）約 0.5 秒。
- 工具：`tools/measure_load.mjs`，用 DevTools Protocol 控制本機 Chrome（無頭模式），記錄每個請求的開始、結束、位元組、連線。
  - **冷快取**：每一輪全新設定檔。**熱快取**：同一個設定檔先載一次、關掉 Chrome 再開來量（＝再次開啟）。
  - 視窗 1400×900，預設設定（DSS2 底圖＋Hα Finkbeiner，視野 18°，框內訊號展開）。
- 量的時間（從 HTML 請求開始）：aladin.js 下載完、第一張底圖切圖、「載入天圖中…」消失、起始畫面切圖到齊（不含 Allsky）。
- 拖曳：起始畫面到齊後 0.5 秒，連續 4 次（小移、小移、放大到 6°、跳到另一區 8°），每次量到切圖到齊。
  IFN：最後按「IFN / 塵埃」，量 IRIS 切圖到齊（40 秒逾時）。
- 本機版是 `python serve.py`；線上版是 GitHub Pages。改後的版本線上量不到（要合併到 main 才會更新），
  所以另外用「每個請求延遲 150 ms」的本機伺服器模擬 GitHub Pages。
- 到 CDS 的網路起伏很大（同一版本兩輪可以差 2 倍），各版本交錯跑、取中位數，括號是最小–最大。
  校準：最後一批裡改後版本的預設畫面跟原版走完全相同的流程，拖曳 4 次合計中位數卻是 16.3 vs 13.1 秒，
  所以**拖曳差 30% 以內都只是雜訊**。

## 改前：時間花在哪裡

### 開啟

線上版冷快取一輪的實際時間（毫秒）：

| 步驟 | 開始 | 結束 | 說明 |
|---|---:|---:|---|
| index.html、app.js（GitHub Pages） | 0 | 470 | |
| aladin.js（jsDelivr，759 KB br 壓縮，解開 2.4 MB） | 470 | 1500 | 要等 app.js 下載、解析完才發現 |
| Aladin 初始化（WebAssembly） | 1500 | 1930 | 純 CPU |
| catalogs.json（232 KB gzip） | 1945 | 2335 | 要等天圖建好才開始抓；「載入天圖中…」要等它 |
| MocServer 查 HiPS 資訊（alaskybis.unistra.fr，新連線） | 1940 | 3400 | 每個圖層一次，回應沒有快取標頭，每次開啟都要重查 |
| 第一批切圖 | 3640 | 4230 | |
| Hα 的 Allsky.fits（11 MB） | 3650 | 20250 | 見下面 |

catalogs.json：線上版 GitHub Pages 已經用 gzip（887 KB → 232 KB）；本機 serve.py 不壓縮，但走 localhost，887 KB 只要 3–6 ms。

### Aladin 挑鏡像（主控台的 irsa CORS 錯誤）

給 Aladin 的是 ID（例如 `CDS/P/DSS2/color`）時，Aladin 3.8.2 會：

1. 向 MocServer 查這個 ID 的 properties（裡面列了所有鏡像，DSS2 有 6 個），查到就用第一個網址（alasky）開始抓切圖；
2. **同時**向每個鏡像要一次 `/properties`（各 1 秒逾時），全部回來後挑最快的，比第二名快不到 10% 就隨機選，
   然後換網址（主控台的 `Change url of … to …`）。

irsa.ipac.caltech.edu 的回應沒有 `Access-Control-Allow-Origin`，被 CORS 擋下，就是主控台那個錯誤；
healpix.ias.u-psud.fr 完全不回應，等到 1 秒逾時。這些探路請求**不會擋住第一批切圖**，錯誤本身無害。
換到哪個鏡像是抽籤：多半是 alaskybis，有一輪換到了 AWS 美東的 stpubdata。

換鏡像其實有一個意外的好處：Allsky.fits 已經在原本的連線上下載，換網址之後的切圖走另一條連線，不會被它擠到（見「試過但沒有採用」）。

所有鏡像都沒有比 CDS 快：從台灣抓 806 KB 的 DSS2 Allsky.jpg，CDS 2.8–3.4 秒、irsa 2.2–4.5 秒、casda（澳洲）3.9 秒、ESA 6.4–8.0 秒。

### IRIS（IFN / 塵埃）載不出來

IRIS 在 MocServer 上的主網址是 cade.irap.omp.eu，從台灣連不上（TCP 逾時）。Aladin 先用它送出整個畫面的切圖，
1 秒後雖然換到 alaskybis，但已經送出的那批不會重送，**IRIS 圖層 40 秒以上都不會出現**（改前每一輪都逾時）。

### 11 MB 的 Allsky.fits

Aladin 3.8.2 對每個 HiPS 圖層都會先抓 `Norder3/Allsky`（原始碼 `src/core/src/tile_fetcher.rs`，沒有選項可以關）。
JPEG 底圖的 Allsky 是 788 KB，但 FITS 疊加圖層的 Allsky.fits 是 32 位元浮點數，**每個約 11 MB**
（CDS 已經用 gzip，12.8 MB 只壓到 11.2 MB），從台灣要 16–30 秒，是開啟時最大的流量（整次開啟約 20 MB，其中 11 MB 是它）。
CDS 有時傳到 20 多秒會把連線關掉（`ERR_CONNECTION_CLOSED`），同一條 HTTP/2 連線上的其他請求一起失敗。

### 冷啟動時切圖和 Allsky 誰先送

Aladin 每 500 ms 才找一次新切圖（`app.rs` 的 `last_time_request_for_new_tiles`），而 Allsky 固定在圖層加入後 100 ms 送出。
HiPS 資訊到的時候如果離上一次找切圖不到 500 ms，切圖就排在 Allsky 後面，在同一條連線上被 Allsky 擠到。
16 輪冷快取裡，切圖先送的 8 輪第一張切圖在 2.2–3.7 秒；Allsky 先送的 8 輪在 3.7–5.2 秒。這是隨機的，我們控制不了。

### 拖曳

每張 DSS2 切圖 40–70 KB，從 CDS 抓 0.6–1.5 秒；放大一級（18° → 6°）一次 22 張、約 2 MB，3–10 秒。
主要是距離和 CDS 本身的速度。每次停下來還會向 hips2fits 抓 2 張切圖（框內訊號 72×72、滑鼠讀值 200×N），各 1–3 秒，不擋天圖。

### 框內訊號啟動時重抓一次

Aladin 用 ResizeObserver 監看天圖大小，一建好就送一次 `resizeChanged`，`refreshHeavy()` 因此在啟動 0.3 秒後又跑一次，
把剛送出的框內訊號請求中斷、再送一次一模一樣的（滑鼠讀值那張也會重抓，但那是版面調整後長寬比真的變了，屬於正常更新）。

### 手機上的框中心讀值

觸控裝置沒有游標，改成固定顯示構圖框中心的數值，但切圖抓到之後沒有重畫，Hα／塵埃的數值永遠停在「…」。

## 改了什麼

1. **IRIS 加上 `startUrl`**（`js/config.js`）：先從 CDS（alasky）讀 properties、抓第一批切圖，Aladin 1 秒後照舊查 MocServer、換到最快的鏡像。
   這是 Aladin 自己內建圖層清單用的選項。startUrl 讀不到時（`errorCallback`）自動改回只用 ID；這個退回用故意寫錯的網址測過。
   其他圖層不變。
2. **aladin.js 和 catalogs.json 預先下載**（`index.html` 的 `<link rel="modulepreload">`、`<link rel="preload" as="fetch" crossorigin>`）：
   HTML 一解析就開始下載。原本 aladin.js 要等 app.js 下載完才發現；目錄要等天圖建好才開始抓。
   app.js 是靜態 import aladin.js 的模組，頂層程式碼要等 aladin.js 下載、執行完才會跑，所以只把 fetch 移到頂層不夠，要靠 `<link>`。
   app.js 的 `fetch("data/catalogs.json")` 沿用這次下載（量測確認只有一個請求）；`crossorigin` 拿掉的話會變成下載兩次。
3. **框內訊號、滑鼠讀值的切圖參數沒變就不重抓**，啟動時少一個被中斷重送的 hips2fits 請求。
4. （另一個 commit）**手機上的框中心讀值**在切圖到了之後重畫。
5. `tools/measure_load.mjs`：這次用的量測腳本，之後可以重量（`--warm` 熱快取、`--quick` 只量開啟）。

## 評估過但沒有做

| 做法 | 為什麼不做 |
|---|---|
| 擋掉 FITS 圖層的 Allsky.fits（最大的流量） | Aladin 抓不到 Allsky 時改抓 12 張 0 階切圖，但視野大於約 50° 時 Hα 會從 6.9′/像素變成 27′/像素，顯示會變。要等 Aladin 新版提供選項 |
| 改用 Hα 的 JPEG 切圖（Allsky 小很多） | JPEG 是 CDS 預先拉伸成 8 位元的，下限／上限（Rayleigh）和拉伸方式就沒有意義了，顯示會變 |
| 換到其他鏡像 | 從台灣量沒有比 CDS 快的；irsa 連線最快但沒有 CORS，WebGL 不能用 |
| 把 Aladin 需要的 HiPS 資訊全部寫死，連 properties 都不抓 | 要自己維護格式、天區比例等欄位，CDS 改了就會壞；而且一樣會遇到上面 Allsky.fits 擠連線的問題 |
| serve.py 對 JSON 做 gzip | 本機走 localhost，887 KB 只要 3–6 ms，壓縮反而多花 CPU；線上版 GitHub Pages 已經壓縮 |
| serve.py 改快取標頭 | 本機重新驗證每個檔案不到 1 ms；改成長快取會讓改完程式重新整理看不到效果 |
| 預設少開圖層 | 預設只有 DSS2＋Hα 一個疊加圖層，再少就改變了預設看到的內容 |

## 還沒解決

- **SFD98（E(B−V) 消光）從台灣載不出來**：唯一的網址 cade.irap.omp.eu 連不上，CDS 沒有鏡像。
  hips2fits（CDS 伺服器端）還算得出框內數值，但天圖上的疊加圖層出不來。需要另外找替代資料或可用的鏡像。
- **FITS 圖層的 Allsky.fits**：每開一個 FITS 疊加圖層就多 11 MB，手機流量和速度都吃虧。可以追蹤 Aladin Lite 新版能不能關掉。
